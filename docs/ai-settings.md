# AI 提交生成与本机设置

对应 [Issue #21](https://github.com/ShaoClean/remote-git/issues/21)。设置按设备保存，应用于所有仓库，不依赖远端 AI CLI。

## 配置与使用

1. 打开“设置 → AI 服务商”，选择 OpenAI、Anthropic、Gemini、DeepSeek，或添加自定义服务商。
2. 填写 API 基础地址，在页面直接输入或粘贴 API Key，启用服务商。桌面版和独立服务均无需配置密钥环境变量。“OpenAI”协议使用 Chat Completions，也支持兼容接口。地址应包括服务的版本路径，不包含具体的 `chat/completions`、`messages`、`models` 路径。
3. 保存配置后，在“测试模型”选择模型并点击“测试连接”，也可获取模型，或手动添加准确的模型 ID 和可选名称。每行右侧的编辑、删除图标支持修改模型 ID、显示名称和删除模型；编辑保留原有启用状态，删除需确认。添加、编辑、删除及启停模型后均需点击“保存配置”。获取模型会保留原有模型、显示名称和启用状态，新发现的模型默认停用；失败时列表不变。手动删除的模型若仍由服务商返回，再次获取时会作为新模型加入并默认停用。
4. 在“提交生成”选择已启用的服务商和模型，设置语言、格式与可选团队约定，再保存。停用当前默认服务商或模型、删除默认模型或修改其 ID 并保存后，会清空默认选择，需要重新选择；只修改显示名称不会影响默认选择。
5. 返回工作区，暂存需要提交的内容，点击摘要输入框右侧的星光图标（悬停时提示“生成提交信息”）。描述下方的辅助工具栏显示当前默认模型与生成范围说明，点击模型可直接进入“提交生成”设置。结果同时填入摘要和描述，可以手动修改、撤销或再次生成，最后由用户点击提交。

“测试模型”可以选择当前服务商已保存的任意模型，包括未启用的模型；进入服务商详情时优先选择该服务商的默认提交模型，其次是首个已启用模型或首个已配置模型。“测试连接”使用选定模型发送一个简短请求，成功提示会显示实际测试的模型 ID。此选择仅用于连接测试，不修改默认提交模型。也可选择“仅测试模型列表接口”；没有已保存模型时默认使用此项。测试与获取模型均使用已保存的配置。服务不支持模型列表接口时，手动添加模型并保存后可以测试生成接口。

已保存密钥只显示配置状态，显隐按钮仅用于新输入的密钥。留空保留原密钥，“清除已有密钥”需要保存后生效。更换 API 地址或协议时需重新输入或清除原密钥，避免将已保存密钥意外发送到另一接口。

HTTP 423 表示上游服务或网关拒绝了请求，界面会提示检查服务状态、账号权限及网关访问规则。模型列表获取失败时保留原配置；空白错误响应不足以判断具体拦截规则，需要结合服务端日志或正常客户端的请求配置排查。

## 数据范围、取消与提交

- 模型服务调用在本地 NestJS 服务内执行，页面不会读取已保存的密钥或直接调用外部模型接口。
- 只读取 `git diff --cached`。禁用外部 diff 程序与 textconv；二进制改动仅提供 Git 的文件/状态信息，不发送二进制补丁。
- 完整暂存差异上限为 **96 KiB（UTF-8）**。超出时拒绝生成并提示减少暂存范围，不会静默截取部分改动。
- 生成请求使用服务端配置版本，读取差异前后及返回结果前校验暂存区的原始变更摘要（包含 blob ID、模式和路径）。配置或暂存内容发生变化时拒绝过期结果。
- 草稿按仓库隔离，生成票据与草稿对象一起校验；取消、编辑、Git 暂存操作、切换仓库/面板或进入设置均会使当前请求失效。HTTP 断开会取消对应 SSH 命令和模型请求，不断开其他 SSH 工作。
- 请求总时限 60 秒，模型响应最多读取 1 MiB，不跟随服务商重定向。认证、额度、超时、空结果、无效 JSON 和状态变化均有可读反馈；错误不会返回模型服务原始正文或认证头。
- 撤销恢复本次生成前的摘要和描述。再次手工编辑后撤销入口收起。草稿保持原来的页面会话语义：刷新应用会清空草稿，进入设置或切换仓库不会。
- AI 不执行暂存、提交或推送。用户确认提交时，提交内容通过 Git 参数转义传递；引号、反引号、`$()` 和真正的换行均按字面处理。

## 持久化与平台

配置保存在应用数据目录的 `ai-settings.json`，通过临时文件加原子替换写入，文件权限为 `0600`。密钥仅以带服务商标识的加密载荷存储，配置读取接口白名单输出公开字段，不返回明文密钥或密文。

| 运行方式       | 密钥保护                                                                    |
| -------------- | --------------------------------------------------------------------------- |
| macOS 桌面     | Electron `safeStorage`，使用系统 Keychain                                   |
| Windows 桌面   | Electron `safeStorage`，使用 DPAPI                                          |
| Linux 桌面     | Electron `safeStorage`，需要可用的系统 secret store；拒绝 `basic_text` 回退 |
| 独立 Node 服务 | AES-256-GCM，自动生成并持久化本机加密密钥，使用本机文件权限保护              |

API Key 只使用用户在设置页保存的值，不读取服务商的环境变量，也不在清除密钥后回退到环境变量。

独立 Node 服务首次启动会在应用数据目录自动创建 `ai-master-key`（32 个随机字节），重启时复用。新建目录权限为 `0700`，密钥文件在 POSIX 系统上限制为当前用户读写（`0600`）；Windows 使用用户数据目录的 ACL。文件密钥依赖本机账户和文件权限保护，具有该目录读取权限的用户可恢复 API Key，保护能力不同于桌面的系统密钥存储。备份时需一起保管 `ai-settings.json` 和 `ai-master-key`，不要提交到仓库。密钥文件损坏或目录不可用时保留原文件并显示错误，不使用明文回退；无需认证的自建服务仍可使用。已保存密钥解密失败时，需要恢复原保护环境或重新输入 API Key。

桌面数据目录沿用应用 `userData`；独立服务沿用 `REMOTE_GIT_DATA_DIR` 或 `~/.remote-git`。AI 配置文件损坏会使 AI 接口提示恢复配置，不阻止 Git 工作区启动，也不会覆盖损坏文件。同一本地服务的不同页面发生配置版本冲突时会拒绝写入，可通过错误提示中的重新加载操作读取新配置。

设置中心复用现有布局 store 与桌面更新状态。布局即时生效并保留恢复默认能力；离开设置不停止更新下载。不支持更新的平台仍可使用其他设置分类。

## 接口与验证

- `GET /api/ai/settings`
- `POST /api/ai/providers`、`PUT /api/ai/providers/:id`
- `POST /api/ai/providers/:id/test`、`POST /api/ai/providers/:id/models`
- `PUT /api/ai/commit-settings`
- `POST /api/ai/repositories/:id/generate`

写入及生成接口携带配置 `revision`；生成只接受仓库 ID 与配置引用，差异由本地服务读取。独立开发服务不使用 `/api` 前缀，Vite 代理自动去除该前缀。桌面继续使用现有主进程注入的会话认证与 CSP。

连接测试请求为 `{ revision, modelId }`：`modelId` 为当前服务商已保存的模型 ID，`null` 表示仅测试模型列表接口。未保存或属于其他服务商的模型会被拒绝；省略此字段保留旧接口的行为（首个已启用模型，无启用模型时测试列表接口）。

OpenAI 协议参考官方 [Chat Completions](https://developers.openai.com/api/reference/chat-completions/overview/) 与 [Create a chat completion](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。具体账号权限、可用模型 ID、代理兼容性以服务商为准；预置模型可以替换。

设计方案见 [Issue #21 Wiki](https://github.com/ShaoClean/remote-git/wiki/Issue-21)；实际执行范围、截图及未验证平台见 [验证记录](https://github.com/ShaoClean/remote-git/wiki/Issue-21-Validation)。
