# 子模块与 Git LFS

对应 [Issue #191](https://github.com/ShaoClean/Alune/issues/191)。

在仓库的“文件”视图中，子模块分组显示路径、当前提交、暂存区记录提交、初始化状态、指针变化／冲突与未提交改动。已初始化子模块会继续列出其嵌套子模块；尚未初始化的模块需要先更新才能读取其内部列表。

- **初始化 / 更新**：执行 `git submodule update --init --recursive`，检出父仓库记录的提交，不追踪远程分支最新提交，不使用 `--force`。
- **同步 URL**：执行 `git submodule sync --recursive`。
- **在新标签中打开**：作为独立仓库加入列表，复用原仓库的本地／SSH 来源；重复打开复用已有登记。

子模块更新沿用执行主机的 Git 凭据和 Alune 代理；SSH 模式下命令在远端运行。错误和取消沿用仓库 Git 操作反馈，部分成功的更新会重新读取状态。改动 Diff 使用 Git 的子模块提交摘要。

LFS 检测、缓存与安装状态均对应**仓库所在主机**。文件预览和 Diff 识别 LFS 指针，显示实际字节数和 SHA-256 OID。已下载的图片从该主机的 LFS 对象缓存读取，并校验大小和 SHA-256；历史版本按各自 OID 读取。预览不会自动联网下载文件，图片沿用 5 MiB 上限。缺少对象时可在该主机运行 `git lfs pull`。非图片 LFS 文件显示元数据。

没有安装 `git-lfs` 时，文件视图提示安装并运行 `git lfs install`。已配置必需 LFS filter 的仓库会对状态／Diff 读取禁用缺失 filter 后重试，普通文件仍可查看；水合 LFS 文件的改动判断在此时可能不准确。暂存、提交和网络操作保留 Git 的失败行为，避免把真实二进制内容误提交为普通 Git blob。

推送／拉取保留 Git LFS hook 与 filter 流程，强制输出 LFS 进度，并在操作反馈中显示上传、下载阶段和失败原文。不包含 LFS 锁定或认证配置管理。

## 开发测试

`packages/ssh-client/tests/submodules-lfs.test.cjs` 使用临时 Git 仓库及回环 SSH/SFTP 服务，覆盖两种来源的嵌套子模块初始化、同步、打开路径、脏工作区保护，以及缺失 git-lfs、损坏缓存、历史图片和普通文件操作。

当 PATH 中有 `git-lfs` 时，另运行真实 LFS 提交、推送到临时裸仓库、克隆、拉取与图片读取测试；没有安装时仅跳过这些明确标记的测试。测试不使用用户的远程仓库或凭据。
