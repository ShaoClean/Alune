# 创建 PR/MR

Alune 可在 GitHub、GitLab.com 和使用 HTTPS 的自建 GitLab 仓库中，基于本地分支创建同仓库 PR/MR。入口位于 PR/MR 页、分支菜单、分支列表，以及分支推送完成后的提示。跨仓库 fork PR 暂不支持。

## 创建流程

1. 在 PR/MR 页选择远端；自建 GitLab 需要确认平台，并关联有写权限的访问令牌。
2. 打开创建表单，目标默认为托管平台的仓库默认分支。可选择或输入其他分支，点击「预览改动」读取提交和文件 Diff。
3. 本地分支尚未完整推送时，点击「推送到远端并设置上游」。推送使用 Git 自身的凭据，与托管平台 API 访问令牌分开。远端的读取地址与推送地址指向不同项目时，需要先调整远程设置。
4. 编辑标题、描述，按需选择草稿、指派人、审阅者及标签，确认后创建。创建成功会打开应用内详情；如果已经存在相同源分支和目标分支的开放请求，可直接打开它。

GitHub 细粒度令牌需要所选仓库的 Pull requests 读写权限，以及用于分支比较、模板读取的 Contents 读取权限。GitLab 写操作需要 `api` 权限及相应项目角色。成员、标签受平台与项目权限限制；创建成功后附加信息设置失败会明确提示，避免重复创建。

预览固定到读取时的源分支和目标分支提交，创建前会重新检查。平台的创建接口使用分支名称，因此提交发出后的并发推送仍以平台实际结果为准。若网络中断导致创建结果不确定，应先刷新列表核对，再决定是否重新提交。

## AI 起草与内容范围

AI 为可选功能；未配置时可正常手动创建。它沿用「提交生成」中选定的服务商、模型和语言，不发送提交生成的自定义提示词，也不执行 AI Review。

AI 仅接收所选分支的提交消息、文件路径、可用文本 Diff、分支名称和目标分支中的 PR/MR 模板。不读取未提交内容，不向 AI 发送托管平台访问令牌。生成结果先独立展示，点击「将此草稿填入表单」后仍可编辑，最终创建需要另行确认。

优先读取 GitHub 的 `.github/pull_request_template.md`（含大写命名），其次仓库根目录和 `docs` 下的对应模板；命名模板目录 `.github/PULL_REQUEST_TEMPLATE` 取按名称排序的首个 Markdown 文件。GitLab 优先读取 `.gitlab/merge_request_templates/Default.md` 或 `default.md`，否则取该目录按名称排序的首个 Markdown 文件。界面展示实际使用的模板路径；无模板时仍可生成。

平台响应最多读取 16 MiB；预览最多展示 100 条提交、300 个文件、每文件 20000 字符及总计 200000 字符的 Diff。缺失、二进制、平台折叠或截断内容会提示。AI 的完整输入最多 60000 字符，其中模板最多 12000 字符，提交消息合计最多 12000 字符，每个文件 Diff 最多 8000 字符；JSON 转义也计入总限制。生成草稿不能替代完整代码审阅及实际测试。

## PR/MR 中心

从左侧主导航进入「PR/MR 中心」，可汇总 Alune 已添加的本机与 SSH 仓库的所有受支持远端。同一托管项目在多个克隆、worktree 或远端中出现时，请求按项目与编号去重；账号下未添加到 Alune 的仓库不会自动加入。

中心支持「全部」「我创建的」「请求我审阅」及仓库、平台、账号、状态和关键词筛选。关键词覆盖标题、编号、作者与分支。个人视图根据各仓库已关联令牌的实际平台账号判断；「请求我审阅」仅包含开放且直接指定该账号为 reviewer 的请求，不展开团队，也不意味着尚未完成审阅。

点击请求在中心内打开全宽详情，可沿用描述、Diff、讨论、评论、审阅、关闭和合并功能。顶部显示操作账号；有多个来源时可手动切换。操作始终绑定打开时的远端与账号关联，配置变化后需刷新并重新确认，不会自动切换账号重试。返回列表保留筛选和滚动位置。

「数据来源」面板显示仓库、远端、账号及读取结果，可配置平台与令牌关联。单个来源失败不会阻断其他来源；未识别账号的来源可能不在个人视图中。来源状态为未读取或失败时，不能据此判断该仓库没有请求。

列表按最近更新排序，使用游标继续读取各来源后续页面。搜索暂未匹配但仍有未扫描页面时，点击「继续查找」；数量仅表示已加载条目。返回缓存超过 60 秒会刷新，支持手动刷新，不在后台定时轮询。游标快照有效期为 10 分钟，过期后重新刷新中心。中心首版继续使用仓库内的创建 PR/MR 入口。
