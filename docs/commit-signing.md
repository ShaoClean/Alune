# 提交签名

在仓库工具条点击「提交签名设置」，查看当前生效的 `commit.gpgsign`、`gpg.format` 和 `user.signingkey`，选择 GPG（OpenPGP）或 SSH 并保存。设置仅写入此仓库的本地 Git 配置；留空密钥会移除仓库的密钥覆盖，继承全局配置或 Git 默认值。Alune 不生成、导入或保存私钥与口令。

开启后，普通提交和「修改上一次提交」遵循签名设置。修改上一次提交会将已暂存内容并入 HEAD，替换提交信息并重新签名；提交已推送时需与协作者协调。弹窗打开后 HEAD 如有变化，修改会被拒绝，请重新读取后确认。

附注标签在 `commit.gpgsign` 或 `tag.gpgsign` 开启时签名，轻量标签不签名。关闭提交签名不会覆盖用户已有的 `tag.gpgsign`；对话框会展示其当前值。

## GPG

在执行 Git 的主机安装 GPG，配置 `user.signingkey` 为已有密钥的 ID 或指纹。桌面启动的进程通常没有终端，需使用可弹窗的 pinentry，或先在终端解锁密钥。若提示缺少密钥、pinentry 无法交互或 agent 不可用，请按错误中的原因检查后重试；Alune 不会自动关闭签名重试提交。

## SSH

需要支持 SSH 签名的 Git 和 OpenSSH。`user.signingkey` 可以是执行主机上的密钥路径，或由 ssh-agent 持有私钥的公钥。带口令的密钥应先通过 `ssh-add` 加载到可访问的 agent。

签名和验证是两项不同配置。验证需在执行主机设置 `gpg.ssh.allowedSignersFile`，文件中的身份与公钥决定哪些签名者受到信任。例如：

```text
alice@example.com ssh-ed25519 AAAA...公钥内容...
```

```sh
git config --local gpg.ssh.allowedSignersFile /完整路径/allowed_signers
```

对于 SSH 远程仓库，以上程序、密钥路径、agent 和信任文件均属于远端主机；本机配置不会自动复制到远端。

## 查看验证状态

提交历史按可见记录分批验证，详情显示签名者和密钥标识。刷新仓库会重新验证，因此更改公钥或信任文件后应刷新。

| 状态           | 含义                                                   |
| -------------- | ------------------------------------------------------ |
| 签名有效       | 执行主机上的 Git 验证通过                              |
| 签名无效       | 签名不匹配，或签名／密钥过期、密钥已撤销；详情显示原因 |
| 未知密钥／信任 | 缺少公钥、SSH 信任配置或验证程序，或签名者身份未受信任 |
| 未签名         | 提交对象没有签名                                       |
| 验证失败       | 验证请求失败或超时，可重试；不等同于签名无效           |

结果取决于执行主机的信任配置，与 GitHub／GitLab 的 Verified 标记不一定相同。
