# 仓库操作条布局重构方案

> 针对当前底部状态栏中「分支 / Worktrees / 获取 / 拉取 / 推送 / 改动 / 提交历史 / 更多」这一排功能的重新规划。
> 涉及代码：`apps/web/src/components/RepositoryStatusActions.tsx`、`WorkspaceStatusBar.tsx`、`Layout.tsx`、`workspace-layout.css`。

## 一、结论先行

**这排按钮不该整体待在底部状态栏。** 它里面混了三种性质完全不同的东西，应该按性质拆到三个地方：

| 功能 | 性质 | 建议位置 |
| --- | --- | --- |
| 改动 / 提交历史 / 分支 / 储藏 / 远程 | **视图导航**（切换主内容区） | 主内容区顶部，左对齐的分段标签 |
| 获取 / 拉取 / 推送 / 刷新 | **执行动作**（触发远程 Git 命令） | 同一行顶部工具条的右侧，带文字标签 |
| 当前分支 / Worktrees | **上下文选择器**（当前在哪） | 顶部工具条左端，与仓库标签形成「仓库 → 分支」层级 |
| 仓库切换 / 连接状态 / 通知 | **只读状态** | 保留在底部状态栏 |

底部状态栏回归它在桌面软件里的本职：**显示状态，不承载高频操作**。

## 二、当前布局的四个具体问题

### 1. 高频操作放在了视线和鼠标的最远端

用户的注意力在中部 Diff 区和右侧改动列表。「暂存文件 → 写提交信息 → 推送」是最高频的动线，现在推送按钮却在屏幕最底部，每次都要做一次长距离往返。底部边缘虽然符合费茨定律（鼠标撞边即停），但这一排按钮的**水平位置会随分支名长度、文件数变化而漂移**（`.status-bar__slot` 是可横向滚动的弹性区域），肌肉记忆无法建立。

### 2. 导航和动作长得一模一样

`RepositoryStatusActions.tsx` 里，「拉取」（执行一次远程操作，不可撤销）和「提交历史」（只是切个视图）渲染成同一个 `StatusButton`，同为 28px 纯图标，只靠一根 1px 的 `.status-bar__divider` 分组。用户无法在点击前预判后果，这是当前「不好用」最直接的来源。

### 3. 数字徽标没有语境

截图里的 `13` 和 `2` 目前只能靠 tooltip 解释（`13` = 落后提交数、`2` = 改动文件数）。裸数字并排出现时，用户会下意识把它们理解为同一量纲，容易误读。

### 4. 靠 `display: none` 做响应式，越窄越不可用

`workspace-layout.css` 的 520px 断点里，分支名、计数徽标、连接名、分隔线被整体隐藏，剩下一排无标签的灰色图标。功能没有降级路径，只是消失了。

## 三、推荐方案 A：新增仓库工具条（顶部第二行）

在现有 48px 标签栏下方插入一行 40px 的仓库工具条，只在打开仓库时出现。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ☰  [ repo-a ×] [ repo-b ×]  +                                       ⊟   │ 48px 标签栏（不变）
├──────────────────────────────────────────────────────────────────────────┤
│ ⌥ 改动 2 │ 提交历史 │ 分支 │ ⋯    ⑂ fix/1031678 ▾  ⊞     ↓ 拉取 13  ↑ 推送 │ 40px 仓库工具条（新增）
├──────────┬───────────────────────────────────────────┬───────────────────┤
│          │                                           │                   │
│  工作区   │              Diff / 主内容                 │    改动 / 列表      │
│  侧边栏   │                                           │                   │
│          │                                           │                   │
├──────────┴───────────────────────────────────────────┴───────────────────┤
│ 📁 conn / repo-a        ☁ 已连接 · SSH 可用            🔔                  │ 38px 状态栏（瘦身）
└──────────────────────────────────────────────────────────────────────────┘
```

### 左区：视图导航（分段控件）

- 改动、提交历史、分支三项常驻，储藏、远程收进 `⋯` 溢出菜单（沿用现有 `Dropdown` 逻辑，只是换了位置和方向 `placement="bottomLeft"`）。
- 使用**选中态填充块 + 文字标签**，而不是当前的底部 2px 下划线。左对齐符合「导航决定下方内容」的阅读顺序。
- 「改动 2」的数字紧跟在文字后面，语义自解释，不再是裸数字。

### 右区：分支上下文 + 同步动作

- 分支胶囊保留 `⑂ fix/1031678 ▾`，点击直接展开分支切换菜单（现在点它是跳到「分支」视图，行为和外观不匹配）。Worktrees 图标紧随其后。
- 同步动作区用**一根分隔线隔开**，并带文字标签：`拉取 13` / `推送`。
- 「获取」降级为拉取按钮旁的下拉项（`拉取 / 获取 / 强制推送 / 刷新仓库`），参考 GitHub Desktop 的单主按钮模式——获取是低频且无破坏性的，不值得占一个一级位置。
- 执行中时按钮内联显示 `LoadingOutlined` + 进度文案，状态栏同步显示一行「正在推送…」，两处都有反馈。

### 底部状态栏保留什么

仓库切换器、SSH 连接状态点、后台同步进度、通知铃铛。全部是只读或低频，且天然适合边缘位置。`.status-bar__slot` 这个 portal 插槽可以直接删除，`RepositoryDetailPage.tsx` 里的 `createPortal` 一并移除，组件层级反而变简单。

### 响应式降级

| 断点 | 表现 |
| --- | --- |
| ≥ 1100px | 全量显示，视图与动作都带文字 |
| 900–1100px | 同步动作收起文字，保留图标 + 数字；视图导航保持文字 |
| 700–900px | 储藏、远程、Worktrees 全部进 `⋯`；分支胶囊最大宽度收到 120px |
| < 700px | 视图导航变为图标分段；分支胶囊只留图标 + 当前分支缩写，点击出全屏选择面板 |

关键差别：**降级是收进菜单，不是直接隐藏**，功能始终可达。

## 四、备选方案

### 方案 B：视图导航进左侧边栏

把「改动 / 提交历史 / 分支 / 储藏 / 远程」做成左侧边栏里当前仓库节点下的二级列表（类似 VS Code 活动栏），顶部工具条只保留分支 + 同步动作。

- 优点：顶部只有一行动作，最清爽；视图数量未来可扩展。
- 缺点：左栏可折叠（`Cmd/Ctrl+B`），折叠后一级导航消失，必须在顶栏做一套 fallback，等于两套实现。**除非确定左栏常驻，否则不建议。**

### 方案 C：原地整改，不搬家

保持底部，但做三件事：动作与导航之间加粗分组（改用 8px 间隔 + 背景色块而非 1px 竖线）、给拉取/推送补文字标签、把推送做成主色按钮。

- 优点：改动量最小，不动布局骨架和现有测试。
- 缺点：只解决了「不美观」，没解决「不好用」——动线长和位置漂移的根因还在。适合作为过渡版本。

## 五、色彩与字体：不引入任何新值

设计稿的所有颜色均取自 `apps/web/src/index.css` 的 `:root`，实现时直接写 `var(--token)` 即可，无需比色。

| 用途 | 令牌 | 色值 |
| --- | --- | --- |
| 推送按钮底色 | `--blue` | `#2563eb` |
| 选中视图底色 | `--blue-soft` | `#eaf1ff` |
| 落后提交计数 | `--orange` | `#d97706` |
| 计数徽标底色 | `--orange-soft` | `#fff5df` |
| 工具条底色 | `--surface-muted` | `#f8fafc` |
| 分隔线与边框 | `--line` | `#e4e8ef` |
| 主文字 | `--text` | `#172033` |
| 次级文字 | `--text-muted` | `#68758a` |

两个例外是 `status-button` 现有的局部色值（`workspace-layout.css` 中未提升为变量）：未选中视图文字 `#61738b`、选中视图文字 `#1d5ecc` 配底色 `#e1ecff` 与描边 `#c8d9f7`。实现时可直接沿用，也可借这次重构提升为全局变量。

字体同样沿用产品现值：界面文字 Inter，分支名、计数与代码 DM Mono（`index.css:1` 已引入）。

## 六、实施路径（按方案 A）

> 本方案已按 issue #49 实施完成，下表记录最终落地的文件与差异。

1. `Layout.tsx`：`app-shell` 的 `grid-template-rows` 从 `48px 1fr 38px` 改为 `48px auto 1fr 32px`，新增 `repositoryToolbarSlot`，只在 `activeRepositoryId` 存在时渲染该行。
2. `RepositoryToolbar.tsx`（替代原 `RepositoryStatusActions.tsx`）：一个组件内分为视图分段、分支上下文与同步动作三区；`ToolbarButton.tsx` 提供 `nav / action / primary / icon` 四种变体。
3. `WorkspaceStatusBar.tsx`：移除 `setRepositorySlot` 与 `.status-bar__slot`，新增仓库路径与同步进度文案位。
4. `RepositoryDetailPage.tsx`：`createPortal` 目标从状态栏插槽换成工具条插槽，`selectPanel` / `runSync` 逻辑不变，`runSync` 增加 `force` 参数。
5. `workspace-layout.css`：新增 `.repository-toolbar` 及其响应式规则；清理 `.status-bar__slot`、`.status-button--branch` 等失效样式。
6. `apps/web/tests/status-bar.test.mjs`：断言目标从状态栏改为工具条，新增溢出菜单可达性与四档断点用例。

实施时另外拆出的支撑文件：

- `BranchPicker.tsx`：分支胶囊点击直接展开的切换菜单（含筛选与新建分支）。
- `WorktreesPanel.tsx`：Worktree 列表内容，供工具条气泡与窄屏全屏面板共用。
- `stores/syncStatusStore.ts`：同步中的操作与文案，工具条按钮与底部状态栏读同一份状态。
- `hooks/useToolbarTier.ts`：四档断点判定，窄屏把功能收进溢出菜单而非隐藏。
- `hooks/useMenuAlign.ts`：菜单从触发点正下方展开，并向左回收到改动列表左缘之外。

### 风险与前置确认

- 新增一行会让主内容区高度净减 34px（新增 40px 工具条，状态栏同时从 38px 瘦到 32px），需确认小屏（≤768px 高）下 Diff 区仍可用；必要时窄高度时把工具条并回 48px 标签栏右侧。
- 现有 `Cmd/Ctrl+B` 等快捷键不受影响；分支胶囊改为「直接切分支」后，进入分支管理视图的入口已在 `⋯` 菜单中补上「分支管理」。
- 「获取」降级为下拉项属于交互降级，若团队认为获取是高频操作，可保留为一级图标按钮。
